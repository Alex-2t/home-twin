# Home Twin Editor

A floor-plan editor: rooms, furniture, lights, sensors and a live 3D view alongside. For now it is a standalone web app (D-016); later the same core will be embedded in Home Assistant (D-015). The sketches it grew out of are in `prototypes/`.

Current state and remaining tasks are in [status.md](../docs/status.md). The documentation was checked against the code on 2026-11-07.

## How to build and open
```
npm install
npm run build          # → dist/index.html, a single file
npm run dev            # rebuilds on every change (the demo homes in demo/ too) and serves http://localhost:8766/
npm test               # core tests (node --test)
```
The demo apartment (the start screen of the standalone editor; not included in the HA dashboard) is a module in `demo/`: `typical.mjs` is an invented typical three-room apartment from the repository, `own.mjs` is the owner's apartment from the neighboring `3d_floor`, local only (`.gitignore`); the build uses `own.mjs` if it exists, and `node build.mjs --demo=typical` picks the typical one explicitly (any module in `demo/` works: `--demo=homes/studio`). Everything shared by the demo (sensors, devices, statistics, weather) is in `demo/kit.mjs`. Build output goes to `src/gen/` and `dist/` (both in `.gitignore`).

The ten typical homes (D-030, [typical-homes.md](../docs/research/typical-homes.md)) are reference plans with their own HA data: the list is `demo/homes.mjs`, the modules are in `demo/homes/` (home 5 is `typical.mjs`); houses are the ground floor for now. `src/core/homes.test.js` (part of `npm test`) runs each through the editor's own code: rooms, openings and walls, furniture conflicts, then the wizard's steps — areas, “Auto-place” lights, suggested sensors, devices. With three designer interiors (loft, minimalist, Japandi) they are the start screen's examples (D-062): a click opens the home with its own HA data; each is finished in a style (`demo/kit.mjs`: STYLES, or the module's own `STYLE` and room finishes) and furnished like a designer interior, every light placed (D-064).

## Saving and files

The plan is saved after edits, undo and redo. A new plan from the start screen or from a file does not erase the previous one: a plan with a photo goes to a backup slot, and “Restore previous plan” (the ⌂ menu, the start screen) swaps them; an empty plan and an untouched demo do not go there. If the browser refuses to write, the indicator shows “Not saved” and offers to download a file. The undo history holds up to 200 steps and survives a reload (IndexedDB, per project); “Version history” in the ⌂ menu holds snapshots after wizard steps, before major edits and every 10 minutes (D-051); the last plan is restored even if it has no rooms yet.

The JSON contains the plan, including light drafts, but not the underlay image. The photo is stored separately in IndexedDB; its position is rolled back together with the scale and rotation of the plan. When another project is opened, the previous photo is removed. An invalid file or an unknown version is rejected before the current plan is replaced. [Save and import checks](../docs/research/persistence-audit-2026-11-07.md).

## Screen layout (D-017, D-018)
- **The whole screen is a canvas, and all controls float above it** as translucent panels:
  - top left — a house icon, which opens the file menu with the apartment name;
  - top center — the modes “Plan / Furniture / Lights / Sensors” with a count of lamps on the plan;
  - right — undo, “Saved” and settings (theme, grid, hotkeys);
  - bottom center — the mode's tools, hand, zoom as a percentage of “whole plan”, “whole plan” and “?”.

  The modes and the bottom panel are centered in the free part of the screen and do not run under the 3D window.
- **Languages (D-036)**: ten — English (source), Russian, German, French, Dutch, Spanish, Chinese, Italian, Polish, Portuguese. English is the source language of UI strings: in code, text is written in English via `t('…')` (`src/i18n/i18n.js`; the key is the string itself, e.g. `t('Done')`; substitutions `{0}`, plurals in ICU). A `|context` suffix disambiguates identical English words with different meanings (`t('Open|verb')` shows “Open” in English; the suffix is dropped on display). The dictionaries `src/i18n/<lang>.json` map English → translation, including `ru.json`; the glossary is in `src/i18n/GLOSSARY.md`. The language is set by `i18n/boot.js` before the other modules: the user's own choice (the “⋯” menu → “Language”, changing it reloads the page) or the system language. The furniture catalog is translated when the module loads; the `shell.html` markup uses `translateDom`. The scanner `node tools/i18n-scan.mjs [--keys]` finds untranslated text outside `t()` and, with `--keys`, writes `keys.json` (the list of all keys); the test `i18n.test.js` checks that dictionaries have no gaps, and the tests forbid Cyrillic in code (except regular expressions and lines marked `allow-cyrillic`). The words used to guess lamp shape, coverage and service sensors are provided in all ten languages.
- **Theme**: “system”, light or dark. Interface and drawing colors are CSS variables in `styles.css`; `draw.js` reads them when the theme changes. The underlay is processed like a scan (`inkMask` in `underlay.js`): photo lighting is evened out, paper becomes transparent, lines are dark on the light theme and light on the dark one. Icons are Lucide (ISC), `src/editor/icons.js`.
- **The plan looks like a drawing.** Walls are cut at a height of 1.2 m and built from the same geometry as 3D (`wallsAt` in `core/geometry.js`). Windows are thin lines, doors up to 1.15 m have an opening arc, lamps glow. While rooms have an error, room outlines are drawn instead of walls.
- **The main view fills the screen**, plan or 3D. **The second is a window in the bottom right corner:**
  - clicking the window or pressing Tab swaps them;
  - the window is resized by dragging its top left corner;
  - “–” collapses it into a button;
  - on a wide screen (from 1100 px) the second view is placed alongside, taking half the screen, with a movable divider.

  When 3D is the main view, the bottom panel has “Day / Night” and “Reset view”.
- **The selection panel** (room, wall, opening, lamp) always sits flush against the object — beside, below or above it, sharing a border; of these places, the one that covers other rooms and the 3D window least is chosen (at an exterior wall, right behind it, outside the plan; beside is slightly preferred to below and above); if every place interferes, it lies over neighboring rooms where it covers least; it never covers the step hint, the top panels or the bottom panel. If it fits flush nowhere — above it, not going under the top panels, the left panel, the banner and the bottom panel; if it fits neither above nor below — beside (right, otherwise left, not onto the 3D window), and only if there is no room there either — on top. For a lamp the panel is above its room, like the question before selection: the room stays uncovered and the panel does not jump. At the right of the first row is a ⋮⋮ handle: the panel can be moved aside; a moved panel stays at its place on the screen — zooming and panning the plan do not move it — while the same thing remains selected (in the “Lights” step, the same room, `ctxPin`); a double click on the handle returns it to its place.
- **3D like a dollhouse:** the facade side facing the camera is hidden together with its windows so the rooms are visible. A wall's side (N, S, E, W) is where its outer face points (`facadeStrips` in `core/geometry.js`); partitions and walls around a gap inside the outline are always visible.
- **3D view (D-028):** the floor is the one chosen for the room (`room.floor`: the “Floor” row of swatches in the room panel and in the “Link rooms to HA” step — eight common ones, `FLOOR_QUICK`; the palette button opens a window with all 24 coverings by section, `FLOOR_GROUPS`, and “Custom color” — `room.floorTint` instead of the covering's base color; the window is `panelPop` in `ui.js`); walls (D-031) — the “Walls” row of the room (`room.wall`, `room.wallTint`) and “Wall finish” in the wall menu, for a shared wall — on each side (`room.wf[i]`); if not chosen, bathroom and toilet get white tile, the rest warm white (`wallGuess`); in 3D — a side map (`bakeFinish`) and a pattern in the wall shader (`FINISH_GLSL` in `core/surfaces.js`); for floors not chosen, a guess by name (`floorGuess` in `core/surfaces.js`): bathroom and toilet — tile, kitchen and balcony — porcelain stoneware, the rest — oak planks along the room's longer side. For walls without a chosen finish, the guess by room type applies. The light is soft, the sun is high and follows the camera (over the left shoulder). Shading at walls and corners is computed from the plan once (`bakeAO`) and stored in the texture; during edits it is coarser, the exact one comes after 200 ms. Neutral tone mapping; in daytime, lamps that are on shine at 20%. Sensor readings (D-033, D-034) are paint on the walls, the “Sensors” mode (`modes/sensors.js`): a list of HA sensors by area, a click puts one on a wall, the tags on the plan are dragged along the walls of any room (`plan.sensors`: `{id, entity, room, at?, label?, k?, c?, under?}` — `k` digit size, `c` own digit color (if absent, matches the wall color; alarming values are still yellow and red; presets — `INKS`), `under` — which sensor it is stacked under; a climate sensor without a room gets the question “Which room is this?”, and the area is also written to HA; “Don't show” — `plan.sensorSkip`); what to suggest and where — `core/sensors.js` (`recommend`, `layoutSensors`, `wallSpot` with positions per side `alts`); in 3D — `setSensors` in `core/scene.js` (a canvas on a plane at the face, the position is chosen again when the camera turns — `chooseLabels`); at the end of the “Lights” step — the question “Show sensor readings on the walls?” (`offer`). The home view (D-035) — the house button in the 3D window and at the bottom (Home) leads to it; if you rotated it by hand — “Save view” (`plan.view`, `getView`/`setHome` in `core/scene.js`); if there is none — the previous angle; sensor labels on the plan follow it (`homeCam`); in the “Sensors” step the first hint is to choose the view. The background (D-032) is a studio: a gradient toward the window edges (`backdrop`) and a stage with a 1 m grid fading toward the edges (`stage` in `core/scene.js`); the shadow under the house comes from the `bakeAO` shading map; colors — `BG` by theme, night and the selected lamp.
- **The left panel floats under the house icon by default.** The pin in its header fixes the panel as a column on the left. A collapsed panel is just its header (“Rooms 6”, “Lights 10/14”). It is open or closed depending on the mode:
  - “Plan” — collapsed (in the wizard steps “Outline” and “Rooms” — always collapsed; if you open it yourself — until the end of the step);
  - “Furniture” — the catalog; an item snaps with its back to a wall, to a corner, to the middle of a wall and to a neighbor along that wall (flush or with edges aligned) — within 12 px on the screen, no farther than 25 cm (`snapToWall(…, snap)`; at the center and at a neighbor — dashed line), Shift — no snapping; for a selected or dragged item — dashed distances to walls by width and by depth in cm (to the nearest; if flush — to the opposite one), a click on a number lets you enter it exactly (“Distance to wall, cm”); all models are custom code in `furniture3d.js` (D-027), Kenney remains only for old duplicates hidden from the catalog (`hidden`). Kitchen as modules: “Base cabinets”, “Wall cabinets” of any length, “Sink”, “Cooktop” (drawers or an oven below it), “Dishwasher”, “Corner cabinet”, “Tall cabinet” (a cupboard or one with an oven), “Range hood” (dome or slanted), “Refrigerator”; bathroom — “Toilet” (floor-standing or wall-hung), “Bathtub”, “Shower stall” (rectangular or half-round), “Washing machine”, “Washbasin”, “Mirror cabinet”, “Heated towel rail”; living room — “Sofa”, “Corner sofa”, “Sofa bed”, “Armchair”, “Coffee table”, “TV”; “Climate” — “Radiator”, “Air conditioner”, “Boiler”, “Electrical panel”, “Network cabinet”; “Garage & outdoor” — car, bicycle, workbench, chest freezer, garden table and chair, lounger, grill (D-030); on the wall — “Wall shelf”, “Coat rack”, “Mirror”; “Curtains”; “Kids' room” — crib, bunk bed, loft bed, changing dresser, high chair, toy shelf; workplace — corner desk, height-adjustable desk, rolling pedestal, monitor; laundry (in “Bathroom”) — dryer, basket, drying rack, ironing board, robot vacuum; storage — corner and utility cabinet, walk-in wardrobe section, display cabinet, sideboard, floor coat stand. `under` slides under a table (`table`) (a chair — up to the seat, an armchair — up to the armrests, a pedestal — entirely) without overlap; a variant may have its own dimensions (`vars` with `{w,d,h}`); `lift: 0` — on the floor, but “Above floor” can be changed (a dryer on a washing machine). Light fixtures in 3D (`fixtureMeshes` in `scene.js`) — each shape has its own look. The entire list from the research (`docs/research/furniture-catalog.md`, 120 items) is in the catalog; “Custom item” (`custom`: a block or cylinder, the name `f.name` is in the panel, `nameOf`) is the last card, and with an empty search — with this name; in “All” first the “Popular” ones (`TOP`), then by rooms; the parts of an item are merged by material (`bake` in `furniture3d.js`); a door obstructs only what is below its top and within the leaf's zone (on its side — the door width, on the other side and at the opening — 30 cm); near the camera only what is higher than 1.5 m is hidden (D-029); a U-shaped sofa is `foot.u` (three arms), a rug (`soft`, low) is drawn under the furniture and selected last, `table` is a number: the tabletop height, for a variant `{z}` is the height above the floor. Variants of one item are chips in the panel (`vars` in the catalog, `f.v` on the item; the third element is how much deeper: an unfolded sofa bed grows forward, the back stays in place), left and right are switched with the “Mirror” button (`mirror`, `f.mx`), colors are individual for each (`colors`: wood, fronts, fabrics, appliances, chrome), the search knows other words too (`tags`: “oven” finds a cooktop and a tall cabinet). L-shaped items (`foot`: a corner cabinet and sofa) are drawn on the plan as the letter L (`footLocal`, `outline`): the niche stays free. At a window an item is centered on the window, curtains take the window width + 40 cm (`fit`) and conflict with nothing (`soft`). Wall-mounted items (`lift`: wall cabinets, TV, range hood) are dashed on the plan, the height of the bottom above the floor is in “Exact dimensions” (“Above floor”, `f.z`); overlap is also computed by height: a TV above a pedestal is fine, a wall cabinet lower than the top of the refrigerator overlaps;
  - “Lights” — while there are lamps without a position (in the “Lights” wizard step — collapsed).

  In “Plan”:
  - the header shows the number of rooms and the total area;
  - for a room — a dot with the floor color from 3D, the area, the number of lamps and a ⚠ with the reason (outline error, lamp without a position, furniture overlaps);
  - on hover — “rename” and “delete”, a double click zooms the plan to the room;
  - the underlay is one row: a thumbnail, opacity (drag the number or use the wheel), “show / hide”, the rest under “⋯”.
  - “Rotate plan” in the bottom panel rotates everything together: photo, rooms, doors, windows, furniture, lamps. Scenario: you uploaded a slightly crooked plan, rotated it so the walls lie straight, and draw on top. Like rotation in Blender and SketchUp — no frame:
    - drag anywhere — the plan rotates around its center, with a line to the cursor, an arc and the angle visible;
    - snaps to 90° and to the angle at which the photo is level; Shift — no snapping;
    - touchpad: in Safari — two-finger rotation, like a map (the `gesturechange` gesture); Chrome, Edge and Firefox do not pass this gesture to sites, so in rotate mode a two-finger left-right swipe rotates there. A pinch is still zoom. Outside rotate mode, fingers do not rotate the plan — so a pinch cannot rotate it by accident. The same applies when rotating only the photo;
    - a click without dragging — done, Esc — cancel; the rotation goes into the history (⌘Z).

    The view (zoom and position) does not change. The plan itself has no scale or shift: sizes are real, the view is moved by the hand.
  - the rotate button in the underlay row — the photo only (when rooms are already drawn and the photo under them has shifted); a frame around the photo, like an image in Figma:
    - drag inside — shift;
    - the circle on top or dragging outside the photo — rotation by any angle, snapping at 0°, 90°, 180° and 270°, Shift — no snapping;
    - corners — scale;
    - a simple click on the photo or outside it, Escape or “Done” — exit;
  - if the rooms have already been traced over a photo with the wrong scale (walls look like threads, areas of hundreds of m²), after “Set scale from a wall” the editor offers “Fit rooms” — the whole plan (rooms, openings, lamps, furniture positions) is scaled together with the photo; wall thicknesses and furniture sizes stay real;
  - “Set scale from a wall” also straightens the photo along that wall — right at the second click, even before the length is entered (apartment walls are almost always at right angles); canceling the input restores the tilt, after input — the “Undo straightening” button.
  - The rotation hints have no buttons (the owner: “nobody will click there”): the angle is visible at the cursor, and the rotation snaps to 90° and to a level photo on its own.

  The user's own choice is remembered for each mode, the key is `\`. In the catalog: search, room labels in one row, cards with size, and at the bottom — “Placed”.
- **Only the user moves the view**: a panel, when it opens, lies on top. “Whole plan” fits the apartment into the part of the screen not covered by panels and the window.
- **Above the selection — an action panel**: name, colors, rotation, “⋯” with exact dimensions (D-014), delete; below the selected item — a size tag.
- Problems — a tag above the bottom panel, only when there are any; a click selects the culprit.
- Layout and theme are stored in `localStorage` under the key `home-twin-editor:ui`.

## Walls (D-019, D-020)
- **Rooms from a single rectangle.** Outline the apartment: drag from corner to corner or click in a corner, then in the opposite one (Esc — cancel one in progress). Then “Split” (S): the line goes through the cursor; the direction follows the mouse movement: move up-down — the line is horizontal and follows the cursor, left-right — vertical (like dragging a ruler). Close to a wall (within 25 px) — parallel to it; the wall the line is parallel to is highlighted. Tab rotates the line and holds the direction until the cursor approaches a wall or leaves the room. A click — a partition, the areas of both parts are shown. The position snaps to corners of other rooms and to the grid; Shift — no snapping. At a wall the cursor becomes ↔ / ↕ — it can be dragged, and a click on it opens its menu. Over the room under the cursor — the same panel as for a selected one, and the room itself is slightly tinted: name, area, “⋯”, trash (appears after 0.15 s; moves to a neighboring room after 0.2 s, and outside rooms and when leaving the plan it hides after 0.35 s — to give time to reach it). If a wall menu is open or a room is selected, the first click elsewhere only closes it. After the first rectangle the tool turns on by itself; with no rooms, “Split” turns on “Room”.
- **A click on a wall** (on the fill or on the line) selects only the piece under the cursor — the section shared with one neighbor or an exterior piece (`wallAt`); so any wall can be removed. The menu above it:
  - length (click — enter);
  - “Window” and “Door” — the opening is placed at the click point (on an exterior wall “Window” comes first, on a wall between rooms — “Door”); if it does not fit, the button is inactive;
  - “Remove wall” — for a wall between rooms, merges them into one (the name and zone come from the larger, a door in the removed wall disappears); an exterior wall has no such item, and an exterior side without a wall (from old plans or after deleting a neighbor) gets its wall back by itself (`closeOuterOpen`). Zones are a separate mechanism on top of rooms, later (D-021, O-008). Old boundaries without a wall (dashed) — “Remove boundary” or “Restore wall”.
- **Windows and doors** (`modes/openings.js`, the core is `addOpening` and neighbors in `core/plan.js`): placed from the wall menu at the click point, centered; if a corner or another opening is nearby, they shift and shrink to the free space, and under 40 cm they are not placed. Sizes: door 80 cm (90 on an exterior wall), window 140 cm, bottom 85 and top 240 cm. A selected opening:
  - drag by the body — it moves along its wall, by the edge — the width changes; step 5 cm (Shift — no step); it does not leave its wall, stops at corners and neighboring openings; while dragging — distances to the corners;
  - the panel: “Door · 80 cm · Rotate · ⋯ · trash” or “Window · 140 cm · trash”; a click on the width — enter a number;
  - “Rotate” cycles through 4 leaf positions (`swing`: hinges at the start or end, inward or outward); a new door opens into the room on whose side you clicked, with hinges at the nearest corner;
  - “⋯” → “No door” — an opening without a leaf (an arch to the kitchen); Delete — remove; in “Select” a door is also selected by clicking its arc.
- **HA areas** (D-024): in the wizard step, a room without a link pulses, with “Which room is this?” above it and chips of HA areas (free ones, then those taken by other rooms — inactive: one area, one room). The order is top to bottom, left to right; a click on another room — choose it yourself (no dragging). At the bottom “Not listed? Add it in Home Assistant or skip — you can do it later”, “Open HA ↗”, “Skip” (`room.noArea`). Shafts and pieces under 1 m² are not asked about. The name of a linked room comes from HA (`ed.syncAreas`: renamed — it changes, deleted — the link is gone); the name field is only for rooms without an area. Later — the house button in the room panel: the same chips and “Unlink”. Lamps do not place themselves — that is the “Lights” step. At the end of the step — “Not on the plan: …”.
- **Two areas in one room** (kitchen-living room): for the room highlighted in the step, on every side longer than 60 cm there is a circle right on its line (in this step it catches the click before the wall; hint “Two areas here? Drag the circle on a side”). Drag the circle inward — the side of the region follows the cursor (step 5 cm, Shift — no step), the cut-off strip is the second part; closer than 30 cm — there is no split. Then the wizard asks about the remaining region, then the strip. For a split room the circle is on the boundary (dashed), and it, as well as the boundary itself, moves it. “Remove split” — one area again. `room.zone={a,b,area,left}`, the parts are `zoneParts`, the side is `zoneFromEdge` in `core/plan.js`; when the room is edited the boundary is recomputed, and if it no longer crosses it, there is no split. Outside the wizard — both rows of chips in the house panel (“Second part”).
- **Deleting a room** (trash, Delete, ✕ in the list): if a room is surrounded by others on almost all sides (an extra strip after a bad split), its area goes to the neighbor with the longest shared wall (`absorbRoom`) — without a hole with walls; the hint says to whom, ⌘Z — undo. A room at an exterior wall (a balcony) is deleted as usual.
- **Shaft, hood duct, column**: room panel → “⋯” → the “Shaft or column” switch. The room becomes a solid wall at full height: no floor, label or area. If a split or a new room produced a piece under 1 m², everything stops: the piece pulses, above it a panel with “⋯” open and the question “Shaft or column?” — “No” / “Yes”. A click elsewhere and Esc only close the question (no wall is placed in “Split”); it asks the first 3 times in each project (a new project — 3 times again); whoever turned the switch on themselves is not asked anymore in this project. The count is stored in the browser by `plan.id`.
- **A split narrower than 10 cm** is not placed: the line turns red, a click does nothing, no hints — usually it is an extra split next to an already placed wall. A click outside the apartment also simply does nothing. “Split” without rooms turns on “Room” with the step “Draw a rectangle”.
- **The wizard step** (“Step 2 of 2…”, “Now split into rooms…”) stays until its “Done” is pressed (`ed.step`). A temporary hint lies on top and, once closed, returns the step; changing the tool does not remove it; in “Furniture” and “Lights” the step is hidden, in “Plan” it is visible again; a new plan resets the step. After “Done” on the “Split” step — the step “Now windows and doors…” (the “Select” tool), then “Now link rooms to Home Assistant…” with the count “Linked N of M” (unlinked labels are paler), then the “Furniture” step in “Furniture” mode (D-026: “drag the highlighted furniture”; with no furniture the “Skip” button, with some — “Done”; `ui.wiz[id] = {furn:true}`), then the “Lights” step in “Lights” mode; its “Done” ends the wizard. The wizard step is stored per project (`ui.wiz[plan.id]`) and is shown again after the page reloads. Steps follow the plan, not the clicks: ⌘Z after the first rectangle or deleting all rooms returns to “Draw a rectangle” (or “Step 2 of 2”), and when a room is restored — “Split” again. “Draw a rectangle” at the start of “Draw from scratch” — without a button, it ends by itself.
- **Dragging a wall** moves it together with the neighbors — those on the other side of this wall, facing it (not through a narrow room between them). The halves of a wall after a “Corner” move separately.
- **A click on the number** of the selected room — enter the side length.
- **Lengths** in all fields are in centimeters (a comma is allowed).
- **Thickness:** two shared ones — in settings (“Exterior walls”, “Interior walls”), stored in the plan (`plan.wall`). The thickness of an individual wall — “⋯ → Per-wall thickness” (off by default); then the wall menu gets a “⋯” with the thickness and a handle on the edge. An interior wall is the gap between rooms, growing in both directions from the axis; an exterior one is `room.wt[i]` on the room's side (0 — no wall). Thicknesses in the plan are always visible in 3D.
- **A new room** flush against a neighbor retreats to the partition by itself; a side almost on the line of a neighboring one (within 30 cm) snaps level, “Undo” leaves the step.

## Lights (D-025)
- **Lamp shape** (`core/fixtures.js`): Chandelier, Pendant, Spots, Line, Strip, Sconce, Floor lamp — tiles with a picture. The shape determines the default position, height and 3D light (body, where it shines). It is guessed from the name, entity and model (`guessForm`: “spots”, GU10 → Spots; “baseboard” → Strip at the floor; “sconce above the bed” → two sconces); the guessed tile is outlined.
- **The “Lights” wizard step** — after the “Furniture” step, in “Lights” mode. The wizard goes through the rooms: the lamp it has reached is immediately placed by the guess and selected, above its room — tiles with the chosen shape. Everything placed and corrected in a room is a single edit: on entry, every lamp of the room gets a snapshot `L.was = {k: room, s: lamp}` (in the plan itself — it survives a reload and “Undo”), and the lamps placed in it are drafts (`L.draft`). “Confirm room” saves the room's lights (snapshots and drafts are cleared) and leads to the next room (`nextRoom`). If you went to another room or finished the step with unsaved changes, the panel asks “Save this room's lights?” (`leaveLines`): “Save placement” — like “Confirm room”, “Discard room changes” — the room's lamps from the snapshots (`discard`); Escape or a click on your own room — stay. Snapshots and drafts are set and cleared without a step of their own in the history (`history.amend`). In the wizard the placement count includes confirmed lamps, and skips are indicated separately. The top badge counts processed lamps, including skipped ones. The order is rooms top to bottom, left to right, and within a room the main light first. In a room with several lamps the panel has a list of all its lamps from HA (`roomList`): shape icon, name, for a strip — “at floor” / “at ceiling”, ✓ for saved ones; a click goes to it (without a position, it becomes a draft, the other drafts remain). When another lamp is selected, it flashes in the apartment (`ha.identify`) and in 3D. A lamp without an area (or whose area is not on the plan) comes at the very end, when no rooms have lamps without a position left: “Where is this light?” and rooms; “No” returns it without a room. When the room is saved, such a lamp gets the room's area written to HA too (`toHA` → `ha.setArea`), if the room has one; a lamp with an area is left alone. When the end is reached, it goes round again to the remaining ones. The lamp the wizard is on is `ui.wiz[<id>].at`, and after a reload it is on the same one. There is no trash and no “Skip” in the wizard (Delete on the last point — the lamp is skipped: the next one in this room, and if everything is skipped, the room is saved by itself; “Skip” — only for a lamp without a room); changing the shape, a click elsewhere and “Undo” stay on the current one. In the panel: the number of chandeliers (evenly along the longer side, `ceilingLayout`), the number and layout of spots (a grid with half-step at walls, in a row, around the perimeter), the number of pendants, a line lengthwise / crosswise / as a frame, the strip height (ceiling or floor), how many sconces and at what height from the floor (in cm, a click selects the number); a floor lamp has no choice — the height is guessed from the name (“night light”, “desk lamp” — 75 cm). The count “Placed N of M · skipped K”. The lamp list in the step is collapsed. 3D smoothly shows the room of the current lamp on its own (`view.focus`: of 8 sides × 2 tilts, the one where walls cover the room's floor least, when equal — the one closer to the default view; the room is centered with neighbors — frame ×2.2; after “Done” — the whole apartment) and the light in 3D is on only in this room — in the others it smoothly goes out (`view.setSolo`); when a placed lamp is selected, only it and the parts of its fixture are lit, the scene smoothly darkens (`setSolo(room, ids)`: the general light is darker than night, the background is night, the lamp itself is twice as bright); a small 3D window (narrower than 440 px) immediately grows smoothly by 20% with an accent ring (class `grow`, once per project — `ui.hints['pipGrow:<id>']`), and the corner it is stretched by pulses for the first 30 seconds or until pressed, also once per project (`ui.hints['pipGrip:<id>']`).
- **Lamp shine in 3D** (`view.shine`, the plan as usual): the lamp does not just go out, it breathes — over 2.6 s it smoothly brightens and fades into warm gold, then a soft echo; around the fixture — a halo (over the walls — for a sconce half is inside the wall), a thin golden ring spreads over the floor with each breath; along a strip and a line a wave of highlights runs back and forth. A lamp that is off lights up for the duration of the shine. If the lamp is not in 3D yet (just placed) — the shine starts as soon as the scene is assembled; if rebuilt midway — highlights at the new place. When: a lamp was selected in the step, added, shape, number, layout, height, a strip piece, dragged, a point deleted, color, the “Flash” button; parts of a fixture shine together with it.
- **Editing on the plan:** while you drag a lamp point or the end of a line — dashed distances to the nearest wall horizontally and vertically, in cm to the wall surface (closer than 15 cm — no distance on that axis). Points can be dragged (spots snap to the center and to each other; the body does not enter the wall — `keepIn`), sconces — along walls, line ends — to the first wall (`clampRay`, snapping to a straight line), the middle of a line moves the piece if it is entirely within one room. Default layouts — no closer than 15 cm to a wall, a line in an L-shaped room — in its own part. “Undo” does not close the lamp panel. Delete — remove a point, a piece of a line or a section of a strip.
- **A strip at the floor on the plan** — 12 cm inside the room and slightly thinner (`shiftSegs`), at the ceiling — at the wall: on the same wall they do not merge; in the data and in 3D — where it actually is. A strip and a line are drawn as solid polylines with rounded joints — no dashes and no double glow at the joints between pieces.
- **A selected lamp on the plan** — shines brighter (the glow is larger and stronger), the other lamps, strips and lines are pale (20%), almost without a glow; for a part of another fixture, bright is its fixture (`draw.js`).
- **Strip** — a solid line along the outline of its cell (walls, moved inward by the wall thickness and 3 cm; `stripContour`): at corners and protrusions it turns without breaks. Where it exists — sections of the outline (`stripRuns`, derived from `L.segments`, one segment per side; `stripSegs` — back). Breaks appear on their own: the boundary of room parts — always, doors — for a strip at the floor (up to the jamb and after, ±5 cm); at the ceiling — solid above the door; “Ceiling / Floor” switches. By default — one, the longest wall (for a strip at the floor — counting without doors), for “curtains” — the walls with windows; then the user drags the end along the outline. For a selected strip: a click on it — a 50 cm break (`stripCut`, hovering shows in red where), a click on a break (dashed) — solid again (`stripFill`), the ends of sections are circles: they are dragged along the outline, go around corners, snap to corners and door edges (Shift — no snap), not shorter than 15 cm, and during the drag the section length is shown (`stripMove`). The cursor at a selected strip takes priority over another strip on the same wall; the other strips and lines are paler at that time. Sections are derived with the breaks of their own kind: at the floor doors do not divide the strip, at the ceiling a cut above the door is its own; “Ceiling / Floor” derives sections by the previous kind. The light in 3D comes from segments of 30 cm and longer. Strips from old plans (pieces along walls) — solid once (`L.loop`). **A strip on furniture** (D-026): the `L.opt` variants “Toe kick” (`plinth`, base cabinets, 4 cm), “Under cabinets” (`under`, the bottom of wall cabinets), “Under bed” (`bed`) — in the panel, only if such furniture stands in this part of the room (`furnOpts`). The segments come from the furniture (`furnStrip`), recomputed on every plan edit (`syncFurnStrips` in `ed.update` and `ed.commit`): if furniture is moved — the strip goes with it, if removed — it falls back to floor or ceiling. The ends of such a strip cannot be dragged or cut. The guess when placing (`furnGuess`): “countertop” → under cabinets, a strip at the floor next to base cabinets → toe kick, “bed” → under bed; if you chose “Floor” or “Ceiling” yourself — along the wall. Sides without a wall (the wall between rooms was removed, `wt = 0`) and the boundary of two areas are breaks for any strip (`stripContour`); an existing strip that runs along them loses that piece on entering “Lights” (`healStrips`, it only shortens).
- **An HA lamp and fixtures:** “It's part of another fixture” (`L.with`; the button has a small “?”, with the explanation as a hover hint, on touch — a tap on it: `tip` in `ui.js`) — the lamp shines from the other's position, one body; “Detach” — separate again. An HA light group whose lamps are also in the list is not shown. A switch of an area is the “It's a light” row in the list (`L.relay`). A lamp without an area on the plan — “Where is this light?” with room chips. “Skip” — `L.skip`. “Flash” (⚡) — `ha.identify`, in the editor it flashes in 3D and with rings on the plan.
- Outside the wizard — the same: a click on a lamp in the list asks for its shape, a lamp is dragged from the list onto the plan; “Auto-place” — all by guess.

## Test panel
Only on localhost, bottom left (`editor/devpanel.js`). Every wizard step has its own snapshot: the plan and the photo underlay in the browser (IndexedDB), nothing leaves it. “Remember: <step>” saves the current state into the snapshot of the current step; after a reload the step is guessed from the plan (lamps on the plan — “Lights”, links to HA — “HA areas”, windows or doors — “Windows & doors”, rooms — “Split”). “→ Step” opens the snapshot right at that step; a dot means the step has its own snapshot, otherwise the nearest earlier one is taken (“Rectangle” — the photo only, no rooms). After a return the project counts as new (its own `id`), and hints are shown again.

## Controls
There is always exactly one tool in the bottom panel (a state machine in `app.js`, `ed.setTool`): select, room and complex shape (“Plan” only), hand, plan rotation. Turning on another one turns the previous one off; a repeated click on the active one, V or Esc — back to select. A rotation interrupted by another tool is kept; Esc during rotation cancels it. Holding the space bar is a temporary hand, the tool does not change (as in Figma).

Plan (as in Figma and Photoshop):
- A labeled button at the bottom: “Outline” on an empty plan, “Wall” when an outline exists. The wall line appears on hover, the first click places it; Tab changes the direction. When the tool is turned on, the previous selection is cleared. In the menu by the arrow next to it — “Room” (draw a separate rectangle, R) and “Wall” (S). When Room is chosen, the button shows “Room” so that the active tool is visible;
- a short click selects an object; holding for 240 ms shows the move cursor without changing the plan. Dragging starts immediately after moving 4 screen pixels, there is no need to wait for the hold;
- when grabbing a wall, the arrows point across it, for windows and doors — along the wall; the resize handles of furniture and the photo account for rotation. Free movement — four arrows, view shift and rotation — a hand grab;
- Esc cancels the current object drag. Losing the grab, window focus or changing the tool also returns the object to its original place; a canceled move is not added to the history;
- to move the view — the “hand” ✋ or H, holding space + mouse, the middle or right button, dragging an empty spot; on a trackpad — two fingers (over the room panel, the banner and the length field, the plan also moves);
- to zoom — the mouse wheel or a trackpad pinch; whole plan — ⤢, Home or Shift+1;
- Shift while dragging — no snapping.

3D (as in Blender): rotate — left or middle button, on a trackpad two fingers; move — Shift + button, right button, Shift + two fingers; zoom — wheel or pinch.

The mouse wheel and trackpad are distinguished by the step of `wheelDelta` (for a wheel it is a multiple of 120). Occasionally a slow vertical trackpad gesture may be taken for a wheel — to be checked on a real trackpad.

## First launch

The start screen: “Upload a plan”, “Draw from scratch”, “Demo home”; with a saved project — “Continue”.

After a photo is uploaded — the area from the documents (`askArea` / `ed.fitArea` in `flows.js`, D-038). “Don't know” lets you specify the ends of a wall and its length. The scale from the first rectangle is approximate; after the rooms are linked it is refined without shafts and, at the user's choice, without the balcony (`plan.docArea`, `plan.docBalcony`, `plan.scaleBy`). The photo is straightened by lines (`tiltOf`, D-040); it can be rotated manually and the original tilt restored.

The main path (`MAND` in `wizard-path.js`): **Outline → Rooms → Windows & doors → Room linking → Furniture → Lights**. Optional (`OPT`): “Sensors on walls” and “Card view”. You can leave the wizard and return at any moment.

Per D-042/D-043 the wizard card is always at the bottom. The first row has the visible stage strip and exit, the second a short instruction, “Back” and the action; details expand with “?”. The hint key does not depend on a changing counter. Hints outside the wizard may use the `ed.aim` area, but it is not the position of the main-path card.

Confirmation and deferral of stages are stored in `plan.onboarding.steps`; actual readiness is recomputed from the plan (`wizard-state.js`). A skip is not completion, a light draft requires room confirmation. The summary lists unfinished stages with jumps to them; “Run setup” returns to the first unfinished one. The last UI step is additionally stored in `ui.wiz` of this browser.

When all rooms are linked (including both zones) or all lights are placed and confirmed, the finish button pulses softly three times after 600 ms, then a thin rim remains. Skips, drafts and unconfirmed light edits do not count as readiness; undoing a link removes the hint. For walls, openings, furniture and sensors there is no complete task list — the user decides when they are done. On hover and keyboard focus the pulsing pauses, and with reduced motion in the system only the rim remains. There is no automatic transition.
